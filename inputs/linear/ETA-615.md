# Trailforks go-live: real graded MTB trails in route planning

Follow-up to the route-planning road-snapping work (PR #196, merged). For mountain biking, "generate a shape and snap it" is the wrong primitive — riders want real trails with a difficulty grade, condition, and legal access, not an invented line that might be a hike-a-bike scramble or cross a footpath illegally. Trailforks (Outside/Pinkbike) is the authoritative source.

## Already done (shipped in PR #196)

A ready-to-enable, credential-gated adapter so this flips on the moment we have access:

* server/src/lib/trailforks.js — searchTrailsNear() + helpers (bboxAround, mapDifficulty, normaliseTrail). No-op (returns []) without credentials.
* GET /api/route-planning/mtb-trails — returns 503 until configured; best-effort otherwise.
* api.routePlanning.mtbTrails() client binding.
* Env documented in server/.env.example: TRAILFORKS_APP_ID, TRAILFORKS_APP_SECRET, TRAILFORKS_API_BASE.
* Tests for everything verifiable now (disabled path, bbox maths, difficulty mapping, normaliser, 503-when-unconfigured).

## Why it can't just be turned on

Trailforks' API is a gated partner API — there is no open public key:

1. Register an app with Trailforks and apply for API access (approval required).
2. Commercial-use licensing + attribution terms apply: must display "Powered by Trailforks", link back, respect their data licence. Loop in legal (legal.md) before launch.

## Remaining work (once credentials exist)

- [ ] Apply for + obtain Trailforks partner API access (App ID + Secret).
- [ ] Set TRAILFORKS_APP_ID / TRAILFORKS_APP_SECRET on Railway.
- [ ] Verify the request shape + field names against a live response (TODO(trailforks) markers): the filter=bbox::… syntax, trails endpoint fields (title/difficulty/distance/alt_climb/latitude/longitude), and the numeric difficulty scale (the green→blue→black→double-black mapping in mapDifficulty is a conservative guess — round UP when unsure).
- [ ] Add a harness mock (tests/harness/mocks/) for the Trailforks call + a route test exercising the live path (per CLAUDE.md "new external service call" rule).
- [ ] Wire the MTB search path: when surface = mtb and Trailforks is available, prefer real trails (LLM curates/matches to the rider's brief), falling back to BRouter snapping when no trail data covers the area.
- [ ] Client UI to surface trails + the required "Powered by Trailforks" attribution.
- [ ] Legal sign-off on the data licence + attribution.

## Notes

* Gravel + MTB snapping (BRouter, surface-aware) already landed in PR #196 and works without Trailforks — the immediately-available gravel/MTB win. This ticket is the higher-fidelity MTB trail-discovery layer.
